# Visual hierarchy lenses

Use these lenses during inspection and grilling. They are prompts for decisions, not a palette or component recipe.

## Information priority

Find the question the interface exists to answer. Rank information by its effect on the user's next decision:

1. Immediate action, exception, or deadline
2. Identity and context needed to act safely
3. Supporting facts needed to compare or verify
4. Historical or administrative detail

When everything uses the same weight, size, color, and spacing, the interface has delegated prioritisation to the user.

## Placement

"First" can mean earliest in reading order, highest on the page, first after sorting, or visible before scrolling. Settle which meanings matter. Put decision-driving information where the supported writing direction, layout, and task flow meet it first.

## Emphasis budget

Strong emphasis is scarce. Spend it on the few conditions that change what the user does next. If five treatments shout, none leads.

Build contrast through several quiet differences before reaching for more color:

- type size and weight
- whitespace and grouping
- alignment and column order
- borders, rails, and tonal backgrounds
- disclosure of secondary detail
- motion only when a live change requires attention

## Semantic color

Give each strong color one stable job within the interface. Derive the mapping from the product's existing tokens and conventions. Keep routine content neutral. Pair every color with text, shape, iconography, or position so meaning survives grayscale and color-vision differences.

Treat red as expensive. It works only while rare.

## Depth

Depth explains containment, layering, selection, or interactivity. Use spacing, tonal layers, borders, and sticky-column separation before shadows. A raised treatment should correspond to a raised interaction or layer. Ordinary rows should not look clickable when only their controls are interactive.

## Competition and precedence

Real items carry several facts at once. Define one primary signal through an explicit precedence rule, then permit secondary information only when it changes the next action. Use stable tie-breaks so the interface does not churn.

Keep presentation priority separate from domain state. A visual "Attention" concept may derive from several domain facts without becoming a stored status.

## Quiet states

Completed, inactive, and historical items should recede without becoming illegible. Empty and loading states should preserve the page's structure. Exceptional completed items may still rise when they require action.

## Proof

Prefer the highest test seam that observes what the user sees and can do. Given representative records and controlled time, assert visible order, labels, available actions, filters, sorting, and accessible control names. Test semantic outcomes rather than private helpers, exact pixels, or utility classes.

A redesign is glanceable when a representative user can identify the first required action without reading every field.
